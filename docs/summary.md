# 吃什么

家里用的一周菜单。它和记账部署在同一台个人服务器上，但是独立的程序、独立的数据库和端口。记账在 18080，吃什么在 18082。两边都直接对外提供 HTTPS，服务器上不跑 nginx。

## 一周菜单

打开后看到从今天起的七天。可以前后翻周。每一天分成早餐、午餐和晚餐，一顿里可以有多道菜。一道菜保存菜名、可选的人数和做法，以及食材清单。

食材只有名字、份量和单位。单位固定为克、毫升、个，避免同一样东西用不同写法拆成两行。同一道菜里，名字、单位和「已备好 / 还要买」都相同的行会合成一行。

勾上表示这行已经备好，不出现在采购里。取消勾选表示还要买。勾选不改家里的库存。

## 家里和采购

「家里」是现在手头的全部食材，同样是名字加份量。新记的一笔如果和已有的名字、单位相同，就加到那一笔上。

把家里的一笔放进某道菜，是一次转移：家里减少，菜下面增加一条已备好的记录；菜里如果已经有同名同单位还要买的份量，先扣掉这部分，扣完仍有剩余才留在已备好的数量里。这样采购单不会继续要求购买刚刚从家里拿出来的东西。多拿的部分留在菜上，标成已有。

从菜上放回家里只作用于已备好的那一行，库存增加，菜上的数量减少。还要买的行保持原样。

采购页不另存一份清单。它把当前这七天里所有未打勾的食材按名字和单位加总，并写明来自哪一天的哪道菜。点「买好了」会把这些行标成已备好。

## 菜谱

菜谱不挂在某一天上。它可以手写，也可以从已经排好的一道菜存下来。同名再存一次会换成新的做法和食材。

新建或修改某一天的菜时，可以从菜谱里导入。导入只填表单，日期和早午晚保持不动，食材都先记成还要买。保存之后才写进这一天。删掉菜谱不会删掉已经排进去的菜。

## 菜谱建议

新菜或编辑时可以按菜名向 DeepSeek 要一份两人份的家常建议。请求里会带上家里已有食材的名字和份量，只为了让建议沿用家里已经在用的叫法，不会因为家里有就少报食材。模型返回的是表单草稿，用户改完保存才落库。没有密钥时这个按钮不出现，手写不受影响。密钥只放在服务器的环境文件里。
